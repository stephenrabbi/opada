## 0. The handover and the brief describe different products

The brief I was given assumes **Supabase, TypeScript, Realtime, a 9pm summary cron, a seed script, menu/config files, leak rules, an extraction eval set of 20 messages, and voice notes processed by Gemini**. **None of these exist in the repository.** What exists:

| Brief assumes | Repository actually has |
|---|---|
| Supabase (Postgres + Auth + RLS + Realtime) | **Neon** Postgres via `@neondatabase/serverless`; no Supabase anywhere |
| TypeScript, typecheck, lint | Plain JS/JSX, minified one-line style in most files; **no TypeScript, no ESLint config** |
| Migrations / schema in repo | **No schema, migrations or seed committed.** Tables (`businesses`, `staff`, `staff_api_tokens`, `entries`, `flags`, `action_audit`, `payments`, `paystack_expected_references`) exist only in Herbert's Neon project |
| `vercel.json`, cron for 9pm summary | No `vercel.json`, no cron, no summary |
| Menu / recipes config, "leak rules" | Three rule functions in `src/rules.js`; inputs are hard-coded constants in `app/page.jsx` and `app/api/demo/checks` |
| 20-message extraction eval | 4 unit tests of the validator with a mocked Gemini response |
| Voice notes → Gemini | Browser Web Speech API → regex parser (`src/voice-report-extract.js`); Google STT v2 proxy exists but is **disabled** by flag |
| Realtime alerts within 60 s | Owner page loads data on button press; no polling, no push, no alerts |
| Auth with owner/staff roles | Long-lived bearer tokens (SHA-256 hashed in DB) pasted into a password box; roles `owner`/`manager`/`staff` |

This is the most important finding. Several roadmap choices depend on it, so it is raised as decision **D1** in §6.

Code that is sound on reading and covered by tests:

- **Rule engine** (`src/rules.js`, `src/process.js`): integer kobo, input validation, overflow guards, and a missing-evidence → `skipped` path instead of treating it as zero. I swept the ₦50 rounding of the margin rule at exact multiples (k × ₦32.50 cost, k ≤ 2000) and found no float error.
- **Paystack webhook** (`app/api/paystack/webhook`): reads the raw body, size-caps it at 100 KB, verifies HMAC-SHA512 with `timingSafeEqual`, accepts only `sk_test_` keys and `domain:"test"` events, **re-verifies the transaction against the Paystack API**, checks the amount against a server-side expected reference, and inserts with `ON CONFLICT (paystack_reference) DO NOTHING`.
- **Ingest** (`/api/ingest`): strict allow-list validation, derives `business_id` from the token (never from the client), and always saves with `needs_review = true`.
- **Gemini extractor** (`src/gemini-extract.js`): structured-output schema, temperature 0, nulls for missing money, validated before use, and nothing is persisted.
- **Flag acknowledgement** (`/api/flags/check`): business-scoped update with the audit insert in one statement.

## 2. Claimed but broken or missing: the core loop

The target loop is: **message in → clean record → rules run → flag with evidence → one-tap action → daily summary**.

| Step | State | Evidence |
|---|---|---|
| Message in (text) | ⚠️ Partial | Staff page posts a **manual form** to `/api/ingest`. The free-text note is stored as `raw_text`, but it isn't parsed by AI |
| Message in (voice) | ⚠️ Partial | Browser speech → regex parser for a few English/Pidgin phrases. Yoruba isn't parsed. Server STT is disabled |
| AI extraction → clean record | ❌ Not wired | `/api/gemini/extract` exists, but **no UI calls it** and it never persists. Never run end to end (handover §3 says so too) |
| Rules run on stored data | ❌ Missing | `processFacts` is called **only with hard-coded constants** (`app/page.jsx`, `/api/demo/checks`). No code aggregates entries/payments per business per day |
| Flag with evidence | ❌ Missing | **No code anywhere inserts into `flags`.** The owner dashboard reads `flags`, so any flag shown in the demo was inserted by hand in Neon |
| One-tap action | ⚠️ API only | `/api/flags/check` exists; **the owner UI has no button that calls it** |
| Alert within 60 s | ❌ Missing | No push, polling, SMS or WhatsApp. The owner presses "Refresh" |
| 9pm daily summary | ❌ Missing | No cron, no summary code |
| AI explanation with number check | ❌ Missing | No explanation generation and no number-verification guard |
| Paystack → reconciliation | ⚠️ Partial | Receipts are stored (webhook path not proven end to end; the one demo receipt came from the manual `/reconcile` endpoint). The transfer rule never consumes them |
| Configurable thresholds per business | ❌ | `thresholds` is a frozen module constant |
| Africa/Lagos day boundaries | ❌ | Only a UI label. No date logic exists to be wrong yet |

**Bottom line:** the pieces at the ends exist (ingest, receipts, rule functions, flag read/ack API, dashboard shell). The middle of the loop (extraction → persistence → rules over stored data → flag creation) does not. The current runbook (`docs/demo-day-runbook.md`) is honest about this, and the brief's "60-second loop" is **not** what the product does today.

## 4. Tech debt

**Fix now (M0/M1, cheap, unblocks everything):**
1. Commit lockfile and switch CI to `npm ci`. Patch Next to 15.5.28.
2. Commit a schema baseline from Neon, then migrations from then on.
3. Un-minify source. Most `app/api/*` and `src/*` files are single 300–1,500-char lines, so review and diffs are near-impossible. A formatter-only commit (Prettier) changes no behaviour.
4. Add ESLint (`next lint`) and make it a CI gate.
5. Collapse the duplicated token-lookup SQL (`ingest`, `gemini/extract` and `webhook` re-implement what `src/staff-auth.js` does).
6. Fix `.env.example`.

**Fix later (M2/M3):**
- TypeScript migration, incremental with `allowJs`, starting with `src/` money/rules code (see D2 in roadmap).
- Proper test layers: unit tests are currently mixed with "UI acceptance" tests that grep JSX source for strings (`test/ui-acceptance.test.js`). These are brittle; replace them with Playwright assertions.
- Inline styles everywhere. Consolidate into `app/opada-ui.css` when the UI is redesigned.
- Legal pages are prototype text and need counsel review (handover Phase G).
